Vežba 7, Zadatak – Rešenje (komande)

Komande za VPC1, VPC2, SW1 i SW2 su kucane na pravim uređajima (Docker gns3/openvswitch sa OVS 2.17 za SW1 i SW2, VPCS za VPC1 i VPC2) i proverene u ovom redosledu. MikroTik komande iz koraka 4 nisu izvršene u test okruženju (MikroTik slika nije bila dostupna): umesto MikroTik-a u testu je radio Linux ruter sa istim VLAN podinterfejsima i adresama. Duže komande su prelomljene znakom \ na kraju reda i mogu se nalepiti u konzolu takve kakve su.

Korak 2 – IP adrese i podrazumevani izlaz na VPC-ovima

VPC1

ip 10.10.10.11/24 10.10.10.1

VPC2

ip 10.10.20.12/24 10.10.20.1
Checking for duplicate address...
VPC1 : 10.10.10.11 255.255.255.0 gateway 10.10.10.1

Checking for duplicate address...
VPC2 : 10.10.20.12 255.255.255.0 gateway 10.10.20.1

VPC-ovi ne znaju ništa o VLAN-ovima: šalju i primaju obične okvire bez oznake. VLAN-u ih dodeljuje port sviča na koji su priključeni.

Korak 3 – SW1: bridge-evi, access i trunk portovi, patch par

Slika pri pokretanju stavlja sve portove u br0; br2 postoji, ali je prazan.

SW1

ovs-vsctl del-port br0 eth1
ovs-vsctl del-port br0 eth2
ovs-vsctl add-port br2 eth1
ovs-vsctl add-port br2 eth2
ovs-vsctl set port eth0 tag=10
ovs-vsctl set port eth1 tag=20
ovs-vsctl set port eth2 trunks=10,20
ovs-vsctl add-port br0 br0-br2 trunks=10,20 \
  -- set interface br0-br2 type=patch options:peer=br2-br0
ovs-vsctl add-port br2 br2-br0 trunks=10,20 \
  -- set interface br2-br0 type=patch options:peer=br0-br2
ovs-vsctl show

Izlaz (samo br0 i br2):

    Bridge br2
        datapath_type: netdev
        Port eth2
            trunks: [10, 20]
            Interface eth2
        Port eth1
            tag: 20
            Interface eth1
        Port br2
            Interface br2
                type: internal
        Port br2-br0
            trunks: [10, 20]
            Interface br2-br0
                type: patch
                options: {peer=br0-br2}
    Bridge br0
        datapath_type: netdev
        Port br0
            Interface br0
                type: internal
        Port eth0
            tag: 10
            Interface eth0
        Port br0-br2
            trunks: [10, 20]
            Interface br0-br2
                type: patch
                options: {peer=br2-br0}

tag: 10 i tag: 20 su access portovi, a trunks: [10, 20] trunk portovi koji propuštaju samo ta dva VLAN-a. Komanda za patch port dodaje port i u istoj transakciji (--) podešava njegov interfejs kao patch, sa drugim krajem kao parom.

Korak 4 – MikroTik: VLAN podinterfejsi (nije izvršeno u testu)

MikroTik

/interface vlan add name=vlan10 vlan-id=10 interface=ether1
/interface vlan add name=vlan20 vlan-id=20 interface=ether1
/ip address add address=10.10.10.1/24 interface=vlan10
/ip address add address=10.10.20.1/24 interface=vlan20
/interface vlan print
/ip address print

Svaki podinterfejs prima i šalje okvire sa jednom VLAN oznakom kroz isti fizički interfejs ether1, a njegova adresa je podrazumevani izlaz za taj VLAN. Rute ka obe podmreže ruter dobija sam, jer su direktno povezane, pa rutira između VLAN-ova bez dodatnih komandi. Ove komande nisu proverene na pravom MikroTik-u; u testu je isti posao radio Linux ruter (podinterfejsi eth0.10 sa 10.10.10.1/24 i eth0.20 sa 10.10.20.1/24, uključeno prosleđivanje paketa).

Korak 5 – SW2: samo OpenFlow pravila

SW2

ovs-vsctl port-to-br eth0
ovs-ofctl del-flows br0
br0

Portovi eth0 i eth1 su u br0. Posle del-flows bridge nema nijedno pravilo i odbacuje sve okvire, pa ping između VPC-ova ne radi:

VPC1

ping 10.10.20.12 -c 1
host (10.10.10.1) not reachable

SW2

ovs-ofctl add-flow br0 "priority=100,in_port=eth0,dl_vlan=10,actions=output:eth1"
ovs-ofctl add-flow br0 "priority=100,in_port=eth0,dl_vlan=20,actions=output:eth1"
ovs-ofctl add-flow br0 "priority=100,in_port=eth1,dl_vlan=10,actions=output:eth0"
ovs-ofctl add-flow br0 "priority=100,in_port=eth1,dl_vlan=20,actions=output:eth0"
ovs-ofctl add-flow br0 "priority=0,actions=drop"
ovs-ofctl --names --no-stats dump-flows br0
 priority=100,in_port=eth0,dl_vlan=10 actions=output:eth1
 priority=100,in_port=eth0,dl_vlan=20 actions=output:eth1
 priority=100,in_port=eth1,dl_vlan=10 actions=output:eth0
 priority=100,in_port=eth1,dl_vlan=20 actions=output:eth0
 priority=0 actions=drop

dl_vlan=10 poklapa samo okvire sa 802.1Q oznakom VLAN-a 10, a akcija output šalje okvir dalje takav kakav je, sa istom oznakom. Okviri drugih VLAN-ova i okviri bez oznake poklapaju samo pravilo priority=0,actions=drop i odbacuju se.
