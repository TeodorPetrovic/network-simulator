1. MikroTik RouterOS i CHR

RouterOS je operativni sistem MikroTik rutera. CHR (Cloud Hosted Router) je njegova verzija za virtuelne mašine i u GNS3 radi kao QEMU uređaj; bez licence radi neograničeno, samo sa brzinom ograničenom na 1 Mbit/s po interfejsu, što je za laboratoriju dovoljno. Interfejsi se zovu ether1, ether2, ... po redosledu adaptera. Podrazumevano CHR ima samo DHCP klijent na ether1, a pri prvoj prijavi (admin, prazna lozinka) traži novu lozinku.

Komandna linija je podeljena na menije (/ip address, /interface vlan, ...). U svakom meniju iste komande rade isto: add dodaje stavku, set menja, remove briše, print prikazuje, a [find uslov] bira stavke po nekom svojstvu (npr. [find name=vlan5]). Taster Tab dopunjava imena komandi i parametara. Svaka izmena se primenjuje i trajno čuva odmah, nema posebne komande za čuvanje; /system backup save i /export služe za kopiju konfiguracije van rutera.

2. Kako se podešavaju neke od opcija na MikroTik-u

Primeri u tabeli koriste druge vrednosti nego zadatak (VLAN 5, mreža 192.168.5.0/24, interfejs ether4).

firewall filter/ip firewall filter add chain=input src-address=192.168.5.0/24 protocol=icmp action=drop
SNMP/snmp set enabled=yes location="Lab 2", /snmp community add name=mon5 addresses=192.168.5.0/24
slanje loga/system logging action add name=srv5 target=remote remote=192.168.5.200
/system logging add topics=critical action=srv5
backup, export/system backup save name=kopija, /export file=kopija, /file print

Firewall filter ima tri lanca: input za pakete upućene samom ruteru, forward za pakete koje ruter prosleđuje i output za pakete koje ruter šalje. Pravila se proveravaju redom i prvo pravilo koje se poklopi odlučuje; paket koji ne poklopi nijedno pravilo se propušta. masquerade u lancu srcnat zamenjuje izvorišnu adresu paketa adresom izlaznog interfejsa. Uslov sa ! je negacija: in-interface=!vlan5 znači "nije došao sa vlan5".

3. SONiC

SONiC (Software for Open Networking in the Cloud) je mrežni operativni sistem otvorenog koda zasnovan na Debian Linux-u. Svaka funkcija (LLDP, SNMP, BGP, upravljanje portovima) radi u svom Docker kontejneru, a sva konfiguracija se nalazi u Redis bazi (CONFIG_DB). U GNS3 se koristi SONiC-VS, virtuelni svič bez pravog hardvera. Prijava je preko konzole kao na Linux-u; komande config ... (uz sudo) menjaju CONFIG_DB, a show ... prikazuju stanje. Izmene važe odmah, ali se posle restarta gube ako se ne sačuvaju komandom sudo config save -y, koja ih upisuje u /etc/sonic/config_db.json.

Portovi se zovu Ethernet0, Ethernet4, Ethernet8, ...: brojevi rastu za 4 jer se port od 40 Gbit/s može podeliti na četiri porta od 10 Gbit/s (npr. Ethernet0 do Ethernet3). Početna konfiguracija SONiC-VS-a pravi rutiranu mrežu: svaki port ima svoju IP adresu (10.0.0.0/31, 10.0.0.2/31, ...) i nijedan nije u VLAN-u.

4. LLDP i SNMP

LLDP (Link Layer Discovery Protocol, IEEE 802.1AB) je protokol kojim uređaj svakih 30 sekundi na svakom portu objavljuje svoje ime, ime porta i upravljačku adresu. Okviri se ne prosleđuju dalje, pa svaki uređaj vidi samo direktno povezane susede. Na SONiC-u je LLDP uključen podrazumevano (show lldp table), a MikroTik pored LLDP-a šalje i svoje MNDP i CDP objave (/ip neighbor print). SNMP (Simple Network Management Protocol) omogućava serveru za nadzor da čita stanje uređaja (ime, interfejse, brojače saobraćaja). U verziji 2c pristup se kontroliše community stringom, koji je u stvari lozinka koja putuje nešifrovano, pa se pristup dodatno ograničava na upravljačku mrežu. Syslog (UDP port 514) šalje poruke iz loga uređaja na centralni server. SNMP i syslog server se dodaju u Vežbi 9.
