Adrese se uklanjaju samo sa portova koji ulaze u VLAN-ove, a zatim se prave VLAN-ovi i članovi. Bez -u port je član sa oznakom (trunk), a sa -u bez oznake (access).

sudo config hostname SW1
sudo config interface ip remove Ethernet0 10.0.0.0/31
sudo config interface ip remove Ethernet4 10.0.0.2/31
sudo config interface ip remove Ethernet8 10.0.0.4/31
sudo config vlan add 10
sudo config vlan add 20
sudo config vlan add 99
sudo config vlan member add 10 Ethernet0
sudo config vlan member add 99 Ethernet0
sudo config vlan member add 10 Ethernet4
sudo config vlan member add 20 Ethernet4
sudo config vlan member add 99 Ethernet4
sudo config vlan member add -u 10 Ethernet8
sudo config interface ip add Vlan99 10.10.99.2/24
sudo config snmp community add lab8 RO
sudo config save -y

Korak 4 – R1: ime, korisnici, VLAN podinterfejsi, adrese

Pri prvoj prijavi (admin, prazna lozinka) RouterOS pita za licencu (n) i traži novu lozinku dva puta: Vezba8admin.

R1

/system identity set name=R1
/user add name=tehnicar group=read password=Tehnicar8
/interface vlan add name=vlan10 vlan-id=10 interface=ether2
/interface vlan add name=vlan99 vlan-id=99 interface=ether2
/ip address add address=10.10.10.1/24 interface=vlan10
/ip address add address=10.10.20.1/24 interface=ether3
/ip address add address=10.10.99.1/24 interface=vlan99

CHR već ima DHCP klijent na ether1 (podrazumevana konfiguracija), pa ether1 dobija adresu od NAT čvora (D = dinamička) i podrazumevanu rutu. Grupa read može da gleda, ali ne i da menja konfiguraciju. ether3 je običan (neoznačen) port u VLAN-u 20, jer je SW2 Ethernet0 access port.

Korak 5 – R1: DHCP, NAT, firewall, SNMP, log, backup

R1

/ip pool add name=pool10 ranges=10.10.10.100-10.10.10.199
/ip dhcp-server add name=dhcp10 interface=vlan10 address-pool=pool10
/ip dhcp-server network add address=10.10.10.0/24 gateway=10.10.10.1 dns-server=1.1.1.1
/ip firewall nat add chain=srcnat out-interface=ether1 action=masquerade
/ip firewall filter add chain=forward in-interface=!vlan99 dst-address=10.10.99.0/24 action=drop
/snmp community set [find default=yes] name=lab8 addresses=10.10.99.0/24
/snmp set enabled=yes location="Server sala" contact=admin@firma.rs
/system logging action add name=nadzor target=remote remote=10.10.99.10
/system logging add topics=info action=nadzor
/system logging add topics=warning action=nadzor
/system logging add topics=error action=nadzor
/system backup save name=R1-v8
/export file=R1-v8

masquerade menja izvorišnu adresu paketa koji izlaze kroz ether1 adresom ether1, koju je R1 dobio DHCP-om. Filter u lancu forward odbacuje samo pakete koji prolaze kroz ruter ka 10.10.99.0/24, a nisu došli sa vlan99; paketi upućeni samom ruteru (10.10.99.1) idu kroz lanac input i nisu pogođeni. Provera:

/ip firewall nat print
/ip firewall filter print
/snmp community print
/system logging print where action=nadzor

Komande su izvršene na MikroTik CHR 7.16.2 i na Docker verziji SONiC-VS-a (docker-sonic-vs, SONiC master), a ne u GNS3 sa SONiC-VS virtuelnom mašinom, pa se MAC adrese, adresa na ether1 i verzija u izlazima mogu razlikovati.
