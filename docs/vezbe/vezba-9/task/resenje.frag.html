Vežba 9, Zadatak – Rešenje (komande)

Komande za NAGIOS, SYSLOG, SERVER1, SERVER2 i VPC1 su izvršene u ovom redosledu na pravim kontejnerima (jasonrivers/nagios sa Nagios Core 4.5.12, vezba9-linux, VPCS) povezanim preko Open vSwitch-a, a prikazani izlazi potiču iz tog testa. Komande za R1 (MikroTik) i SONiC nisu izvršene (ti uređaji nisu bili dostupni), pa su u izlazima testa R1 i SONiC u stanju DOWN. Blokovi se mogu nalepiti u konzolu takvi kakvi su.

Grupe hostova i servis HTTP dodaju se na kraj istog fajla (>>), pa se konfiguracija proverava i učitava:

cat >> /opt/nagios/etc/conf.d/lab9.cfg <<'EOF'
define hostgroup {
    hostgroup_name  serveri
    alias           Serveri
    members         SERVER1,SERVER2
}
define hostgroup {
    hostgroup_name  mrezni-uredjaji
    alias           Mrezni uredjaji
    members         R1,SONiC
}
define service {
    use                  generic-service
    hostgroup_name       serveri
    service_description  HTTP
    check_command        check_http
    check_interval       1
    retry_interval       1
    max_check_attempts   2
}
EOF
/opt/nagios/bin/nagios -v /opt/nagios/etc/nagios.cfg | tail -3

Posle jednog do dva minuta svi hostovi su provereni. Stanje se vidi u veb interfejsu (Hosts), a isto daje i JSON CGI Nagios-a:

S="http://nagiosadmin:nagios@localhost/nagios/cgi-bin/statusjson.cgi"
curl -s "$S?query=hostlist" | jq -c .data.hostlist
{"R1":4,"SERVER1":2,"SERVER2":2,"SONiC":4,"SYSLOG":2,"VPC1":2,"localhost":2}

Kod stanja hosta: 1 = PENDING (još nije proveren), 2 = UP, 4 = DOWN. localhost je sam NAGIOS iz podrazumevane konfiguracije slike. R1 i SONiC su u testu DOWN jer ih nije bilo u mreži; u laboratoriji sa Vežbom 8 su UP.

Korak 4 – komanda, servis SNMP uptime i kontakt

NAGIOS

cat > /opt/nagios/etc/conf.d/nadzor.cfg <<'EOF'
define command {
    command_name  check_snmp_lab9
    command_line  $USER1$/check_snmp -H $HOSTADDRESS$ -P 2c -C $ARG1$ -o $ARG2$
}
define service {
    use                  generic-service
    hostgroup_name       serveri,mrezni-uredjaji
    service_description  SNMP uptime
    check_command        check_snmp_lab9!lab9!1.3.6.1.2.1.1.3.0
    check_interval       1
    retry_interval       1
    max_check_attempts   2
}
define command {
    command_name  notify-host-by-syslog
    command_line  /usr/bin/logger -n 10.9.0.20 -P 514 -d -t nagios \
"HOST $NOTIFICATIONTYPE$: $HOSTNAME$ je $HOSTSTATE$"
}
define command {
    command_name  notify-service-by-syslog
    command_line  /usr/bin/logger -n 10.9.0.20 -P 514 -d -t nagios \
"SERVIS $NOTIFICATIONTYPE$: $HOSTNAME$/$SERVICEDESC$ je $SERVICESTATE$"
}
define contact {
    contact_name                   dezurni
    use                            generic-contact
    alias                          Dezurni administrator
    contactgroups                  admins
    host_notification_commands     notify-host-by-syslog
    service_notification_commands  notify-service-by-syslog
}
EOF
/opt/nagios/bin/nagios -v /opt/nagios/etc/nagios.cfg | tail -3
sv reload nagios
Total Errors:   0

Things look okay - No serious problems were detected during the pre-flight check
ok: run: nagios: (pid 318) 75s

Znak \ na kraju reda u Nagios konfiguraciji nastavlja direktivu u sledećem redu. Šablon generic-contact daje periode (24x7) i vrste obaveštenja; kontakt menja samo komande. Grupa admins sada ima dva člana: nagiosadmin (e-pošta) i dezurni (syslog).

S="http://nagiosadmin:nagios@localhost/nagios/cgi-bin/statusjson.cgi"
curl -s "$S?query=servicelist&hostgroup=serveri" | jq -c .data.servicelist
{"SERVER1":{"HTTP":2,"SNMP uptime":2},"SERVER2":{"HTTP":2,"SNMP uptime":2}}

Kod stanja servisa: 2 = OK, 16 = CRITICAL.

Korak 7 – ispad servera SERVER2

Čvor SERVER2 se zaustavlja u GNS3 (Stop). Posle dva do tri minuta:

NAGIOS

S="http://nagiosadmin:nagios@localhost/nagios/cgi-bin/statusjson.cgi"
curl -s "$S?query=host&hostname=SERVER2" | \
  jq -c '.data.host | {status, state_type, current_attempt, plugin_output}'
curl -s "$S?query=servicelist&hostname=SERVER2" | jq -c .data.servicelist
{"status":4,"state_type":1,"current_attempt":2,"plugin_output":"CRITICAL - Host Unreachable (10.9.0.32)"}
{"SERVER2":{"HTTP":16,"SNMP uptime":16}}

SYSLOG

grep SERVER2 /var/log/mreza/NAGIOS.log
2026-11-19T18:49:23.550039+00:00 NAGIOS nagios HOST PROBLEM: SERVER2 je DOWN

Odgovori na pitanja:

  • Host SERVER2 je DOWN (status 4), a servisi HTTP i SNMP uptime CRITICAL (16). Prva neuspešna provera daje SOFT DOWN; posle druge (max_check_attempts 2) stanje je HARD (state_type 1, current_attempt 2). Isto se vidi u veb interfejsu (crveno polje, kolona Attempt 2/2).
  • Na SYSLOG je stigla poruka HOST PROBLEM: SERVER2 je DOWN od hosta NAGIOS, sa oznakom nagios, u fajlu /var/log/mreza/NAGIOS.log. Poslao ju je kontakt dezurni komandom notify-host-by-syslog kada je stanje postalo HARD.
  • Nagios ne šalje obaveštenja za servise hosta koji je DOWN: uzrok je ispad hosta, pa bi poruke o servisima bile suvišne. Zato u logu nema poruke SERVIS PROBLEM za SERVER2.
  • snmpget sa zajednicom public ne dobija odgovor (Timeout: No Response from 10.9.0.31.), jer je na agentu podešena samo zajednica lab9.
