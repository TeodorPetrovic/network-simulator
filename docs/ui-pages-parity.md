# UI pages and dialog parity inventory

Reference: GNS3 3.1 Web UI under `/tmp/gns3-research/gns3-web-ui/src/app`, especially `app-routing.module.ts` and `components/{projects,preferences,template,servers,settings,system-status,installed-software,snapshots,project-map/new-template-dialog,project-map/import-appliance,project-map/node-editors}`. This is a behavior and field inventory; no upstream implementation is copied.

Status reflects the PAGES implementation in this checkout. A UI action is marked partial when the form exists but depends on a backend route or runtime behavior that can still return unavailable. Fields marked Pending backend are visible for parity and are not submitted as active settings.

## PAGES implementation boundary

The port uses TanStack file routes under `frontend/src/routes`, React/shadcn components, and GNS3-shaped `/v3` API calls. Pages whose backend routes are still being built call the planned GNS3 `/v3` route in `api.ts`, report an actionable unavailable state on failure, and never emulate a successful mutation locally. Template fields are editable only where their values are consumed by the Rust runtime; other upstream fields remain visible as pending-backend fields and are not submitted as active settings. IOU, VirtualBox, VMware, and GNS3 VM stay explicit unsupported placeholders.
